# SEO metadata backfill — operator runbook

This directory hosts the **committed CSV diff reports** that drive the
5-PR SEO metadata rescue plan (see
[`.github/prompts/seo-metadata-contract.md`](../../.github/prompts/seo-metadata-contract.md)
for the editorial contract). The reports are generated by
[`scripts/backfill-article-metadata.ts`](../../scripts/backfill-article-metadata.ts)
and consumed by PRs 3 / 4 / 5.

## Contents

| File | Produced by | Consumed by |
| ---- | ----------- | ----------- |
| `diff-report-YYYY-MM-DD.csv` | `scripts/backfill-article-metadata.ts --dry-run` (PR 2) | PRs 3, 4, 5 |
| `rewrite-report-YYYY-MM-DD.csv` | `scripts/rewrite-article-metadata.ts --dry-run` (legacy, Tier B preview) | Reviewer only |
| `README.md` | This file | Reviewers / maintainers |

## Regenerating the diff report

```bash
# 1. Scan every news/*.html and emit today's CSV.
npm run backfill-metadata -- --dry-run \
    --output=analysis/metadata-backfill/diff-report-$(date +%F).csv

# 2. Commit the file so reviewers can inspect tier classification.
git add analysis/metadata-backfill/diff-report-$(date +%F).csv
git commit -m "chore(seo): refresh metadata backfill diff report"
```

The scan is read-only — no HTML files on disk are modified by PR 2.

## CSV schema

The CSV is RFC 4180 comma-separated, UTF-8, with a single header row:

```
file_path,date,subfolder,lang,tier,field,violation_code,before,after,reason
```

| Column | Meaning |
| ------ | ------- |
| `file_path` | Repo-relative path to the `news/*.html` article. |
| `date` | ISO date pulled from the filename. |
| `subfolder` | Analysis subfolder slug (e.g. `evening-analysis`). |
| `lang` | Language code pulled from the `-$LANG.html` suffix. |
| `tier` | `A`, `B`, or `C` — see "Tier classification" below. |
| `field` | `title` or `description`. Blank if the row is a tier-only row for a contract-green article. |
| `violation_code` | Stable machine-readable code from `scripts/backfill-lib/contract-checker.ts`. |
| `before` | Observed offending value. |
| `after` | Planned post-backfill value. **Blank in PR 2** — filled in by PRs 3/4/5 when they run. |
| `reason` | Diagnostic string combining the tier rationale and the contract check message. |

## Tier classification

| Tier | Description | Fix mechanism | PR |
| ---- | ----------- | ------------- | -- |
| **A** | Source markdown (`executive-brief.md` or `article.$LANG.md`) exists on disk under `analysis/daily/$DATE/$SUBFOLDER/`. | Re-run `renderArticleHtml` against the source. | PR 3 |
| **B** | Source markdown is gone (typically legacy pre-aggregator articles). | In-place HTML rewrite using `scripts/rewrite-article-metadata.ts`. | PR 4 |
| **C** | Non-EN article whose description is below its per-language floor (or title above ceiling). | Re-translate from the EN sibling via `news-translate`. | PR 5 |

A single article can carry **multiple tiers** — a Japanese article with
a source markdown on disk *and* a too-short description will show up
under both A and C, and both PRs will touch it. Uncategorised rows
(every file should be in ≥ 1 tier) are a classifier bug.

| Code | Field | Contract § |

| `TITLE_HAS_ISO_DATE` | `title` | §2.2 |
| `TITLE_ENDS_WITH_BRAND` | `title` | §2.2 (chrome template double-brand) |
| `TITLE_HAS_BANNED_PHRASE` | `title` | §2.2 |

## CLI reference

```bash
npx tsx scripts/backfill-article-metadata.ts [flags]
```

| Flag | Effect |
| ---- | ------ |
| `--dry-run` | Scan only; emit CSV; exit `0`. **Default behaviour.** |
| `--check` | Scan only; emit CSV; exit `1` when any article violates the contract. |
| `--apply` | **Reserved for PRs 3–5.** Fails fast with exit `2` in PR 2. |
| `--tier=A\|B\|C\|all` | Restrict classification to a tier subset. `all` is the default. |
| `--lang=sv,no,de` | Restrict scan to comma-separated language codes. |
| `--date-from=YYYY-MM-DD` | Lower bound (inclusive) on article date. |
| `--date-to=YYYY-MM-DD` | Upper bound (inclusive) on article date. |
| `--output=<path>` | CSV output path. |
| `--news-dir=<path>` | Override the `news/` directory (test-only). |
| `--quiet` | Suppress the summary line on stderr. |

## Exit codes

| Code | Meaning |
| ---- | ------- |
| `0` | `--dry-run` ran to completion, or `--check` found no violations. |
| `1` | `--check` found ≥ 1 violation, or a runtime error. |
| `2` | CLI misuse (unknown flag, bad value, `--apply` in PR 2). |

## Expected exit codes during the 5-PR rollout

| State | `--check` exits | Notes |
| ----- | --------------- | ----- |
| After PR 2 (today) | **1** | ~2,736 articles violate the contract; the CSV is the source of truth for the backlog. |
| After PR 3 (Tier A regenerate) | **1** | Tier A articles fixed (~55 files); Tier B + C still dirty. |
| After PR 4 (Tier B rewrite) | **1** | Tier A + B fixed; Tier C still dirty on the non-EN translations. |
| After PR 5 (Tier C translation repair + CI gate) | **0** | Clean. The same command is wired into CI as a blocking quality gate. |

## Reproducing a single row

Pick any row from the CSV. To reproduce its violation set locally:

```bash
npx tsx scripts/backfill-article-metadata.ts \
    --dry-run \
    --lang=$LANG_FROM_ROW \
    --date-from=$DATE --date-to=$DATE \
    --output=/tmp/single-row.csv
grep '<filename>' /tmp/single-row.csv
```

The output should match the committed row byte-for-byte (the tool is
deterministic; it only reads filesystem state and passes no
environment-dependent input into the violation messages).

## CSV merge conflicts

The CSV is ordered deterministically (alphabetical filename → tier
order → violation index). When two parallel PRs touch the report:

1. **Do not hand-edit the CSV.** Regenerate it:
   ```bash
   npm run backfill-metadata -- --dry-run \
       --output=analysis/metadata-backfill/diff-report-$(date +%F).csv
   ```
2. Commit the regenerated file; the merge is resolved by overwrite.
3. If two PRs carry *different* `diff-report-YYYY-MM-DD.csv`
   filenames, keep both — they are historical snapshots.
